# Mobile Delta Skin Renderer

## Objective
Replace the mobile-only static console artwork/coordinate overlay with a reusable renderer for a documented, safe subset of Delta Emulator skins, while preserving the desktop presentation, existing game lifecycle, and keyboard controls.

## Problem and rationale
The play page already renders a fixed-resolution canvas and the Candybar handheld PNGs in orientation-specific CSS, but touch locations and artwork are coupled to stylesheet percentages. The repository contains pre-existing uncommitted touch-control/test work. A parsed skin model and input adapter should make the screen and control geometry follow `info.json` without creating a second game state or restarting the engine on rotation.

## User decisions and constraints
- User selected **keep the current game scope**: do not add emulator-style quick save/load or fast-forward features. Unsupported custom Delta actions in Candybar must be clearly reported/documented, not silently presented as working controls.
- Keep desktop UI and keyboard input unchanged. Do not rewrite game rules, scoring, or the engine lifecycle.
- Use the existing `Candybar_GBC_DeltaAdvance.deltaskin` configuration and the already-integrated, user-authorized portrait/landscape artwork. Preserve attribution.
- Never modify the pre-existing untracked `bun.lock` or generated Playwright `test-results/` artifacts.
- Current worktree already contains uncommitted changes in `app/globals.css`, `components/GameCanvas.tsx`, `package.json`, `package-lock.json`, plus Playwright files and `odd/tasks/mobile-touch-controls.md`; preserve and reconcile them rather than resetting or replacing them.
- The user previously prohibited commit/push without renewed authorization; on 2026-10-09 they explicitly authorized committing this feature and pushing it to `master`. Exclude `bun.lock` and generated `test-results/`.
- DSK-3 input semantics: the user chose to keep cardinal-only game movement and make the most recently pressed still-active direction win; do not add diagonal gameplay.

## Format research and initial support boundary
- The selected `.deltaskin` is a ZIP archive containing root `info.json` and PNG orientation assets. Its GBC portrait/landscape mappings are `1320×2868` and `2868×1320`; screen source is `160×144`, with portrait output `(180,454,960,864)` and landscape output `(874,144,1120,1008)`.
- Implement and test: ZIP/root `info.json`; iPhone `standard`/`edgeToEdge` representation selection; portrait/landscape configurations; PNG asset references; `mappingSize`; `items` list inputs and directional input dictionaries; item/orientation `extendedEdges`; screen `inputFrame`/`outputFrame`; translucency/debug flags where meaningful; safe scaling and aspect-preserving screen placement.
- Reject or clearly identify unsupported archives/configurations; never assume every `.deltaskin` is usable. The initial runtime does not implement Delta emulator custom operations (`quickSave`, `quickLoad`, fast-forward), PDF rasterization/CoreImage filters, thumbsticks, Nintendo DS touch-coordinate forwarding, or emulator-only save states. Document these limitations and map only actions the existing game actually supports.
- Delta coordinates are points in the skin's `mappingSize`, with origin at top-left. Source documentation: https://github.com/noah978/Delta-Docs/blob/master/skins/README.md (community format guide; it warns that properties may change).

## Architecture plan
- Keep `app/play/page.tsx` as the game-stage/state owner and select the mobile renderer only when touch capability and viewport measurements qualify; leave desktop rendering intact.
- Keep `components/GameCanvas.tsx` as the single canvas/RAF owner. Use its existing engine input boundary through a game-input adapter; do not remount or resize the backing buffer on rotation.
- Replace static coordinate-specific mobile presentation in `app/globals.css` with skin-coordinate layers, orientation-aware sizing, safe-area handling, and an explicit horizontal fallback when metadata lacks landscape.
- Add pure `lib/delta-skins/` parsing/scaling/input mapping and reusable `components/retro-console/` renderer/control/haptics components. Load user-selected `.deltaskin` archives with native browser APIs plus a small ZIP reader; keep the bundled Candybar PNG assets as the default and persist only user preferences/skin data with appropriate browser storage.
- Add deterministic parser/scaling/input tests and mobile/desktop UI regression tests; document supported fields, unsupported Delta features, and device-test limits.

## Acceptance criteria
- Desktop presentation/keyboard/gameplay remain unchanged; mobile console appears only for touch-capable compact viewports.
- Portrait and landscape use the correct Delta mapping, safe-area-aware viewport sizing, and proportional/pixelated canvas output without restarting the game.
- The visible cardinal D-pad, A/B and available pause controls route to existing game inputs; the most recently pressed active direction wins without adding diagonal movement. Simultaneous pointers, holds, drags, cancellation and focus loss release correctly.
- Touch feedback is immediate; vibration is optional, preference-backed, and silently unavailable on unsupported browsers.
- Parser, scaling, and input lifecycle have deterministic tests. Compatibility and limitations are documented; unsupported emulator actions are not claimed to work.
